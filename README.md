# Система обнаружения препятствий на пути метрополитена

Обнаружение посторонних объектов на пути перед беспилотным поездом метро
по данным лидара Hesai OT128 (А . Система работает в реальном времени на бортовом
компьютере (ROS 2 Humble, Docker) и сообщает о препятствии, расстоянии до него,
его смещении от оси пути и высоте.

## Описание

Единственный вход системы - поток облаков точек с лидара Hesai OT128 (128 лучей,
10 кадров в секунду). Никакие другие датчики не используются: собственное движение
поезда оценивается по самим облакам точек. За каждый кадр (0,1 с) система строит
геометрию пути и тоннеля, выделяет габаритный коридор поезда (2,1 x 3 м) и проверяет,
не попал ли в него посторонний объект. Тревога поднимается только после подтверждения
объекта на нескольких кадрах подряд.

## Архитектура

Узел ROS 2 (`ros/metro_detector`) принимает `sensor_msgs/PointCloud2`, декодирует облако
без покадровой обработки на Python, при необходимости перестраивает его на регулярную
сетку датчика и передаёт в движок обнаружения (`libmetro_core.so`, библиотека с C ABI).
Движок за один вызов выполняет одометрию, построение геометрии пути и тоннеля,
обнаружение и сопровождение объектов и возвращает список тревог. Узел публикует результат
в топики ROS 2. Один независимый трекер на каждый входной топик.

```
PointCloud2 -> декодирование -> [перестройка на сетку, если облако не в формате драйвера]
            -> libmetro_core.so: одометрия (ICP + захват скорости на разгоне)
               -> геометрия пути -> обнаружение -> сопровождение -> тревоги
            -> /metro/alerts, /metro/obstacle, /metro/obstacle_distance,
               /metro/markers, /metro/status, /diagnostics
```

См. [docs/architecture.md](docs/architecture.md).

## Алгоритм обнаружения

Кадр лидара -> одометрия по облакам точек (ICP) -> поиск рельсов и оси пути (в том числе
на кривых) -> модель сечения тоннеля (стены и свод) -> габаритный коридор поезда 2,1 x 3 м
-> подтверждение объекта на нескольких кадрах -> тревога с расстоянием, смещением и высотой.

Полное описание этапов -- в [docs/algorithm.md](docs/algorithm.md). Численные пороги и непосредственный влгоритм
обнаружения являются интеллектуальной собственностью и поставляются в зашифрованном виде
внутри движка (см. раздел «Активация и лицензирование»).

## Сборка и запуск

Порядок соответствует требованию стенда: `docker build` -> `docker run` -> `ros2 bag play`.

```bash
# 1. Сборка образа (из корня репозитория; на этапе сборки нужен интернет -- см. активацию)
docker build -f ros/Dockerfile -t metro_detector .

# 2. Запуск узла (host-сеть, чтобы видеть топики на хосте; во время работы интернет не нужен)
docker run --rm -it --net=host --ipc=host metro_detector

# 3. Проигрывание записи (во втором терминале)
docker run --rm -it --net=host --ipc=host -v /path/to/bags:/bags metro_detector \
    ros2 bag play /bags/roundT_doubleT \
    --qos-profile-overrides-path /opt/metro/tools/qos_replay.yaml
```

Переопределение QoS (reliable, глубина 200) обязательно: без него `ros2 bag play`
теряет 3-5 % кадров на 10 Гц, что ухудшает сопровождение. Полный список параметров узла,
формат входа и метрики производительности -- в [ros/README.md](ros/README.md).

## Эксперименты и результаты

Кратко (подробности в [docs/experiments.md](docs/experiments.md)):

- обнаружение объектов организатора (люди, барабаны с кабелем, лестницы и др.) на дальностях
  порядка 100-130 м на движущихся записях;
- ноль ложных тревог на чистом наборе записей без препятствий;
- устойчивость к потере кадров: одометрия учитывает метки времени и «перешагивает» пропущенные
  кадры, не теряя захват скорости;
- время обработки одного кадра в реальном Docker на локальном тестовом стенде в средних пределах 68-80 мс
  для сенсора Hesai OT128, что укладывается в 10 Гц. На сенсоре типа Livox (~900тыс поинтов, нежели чем 300тыс)
  скорость порядка 85-112 мс. Скорость на целевом стенде (Intel i7-9700E) будет выше

Публикуемые топики: `/metro/alerts` (JSON), `/metro/obstacle` (Bool),
`/metro/obstacle_distance` (Float32, `-1` если препятствия нет), `/metro/markers`,
`/metro/status` (JSON), `/diagnostics`.

## Видео

Демонстрационные ролики: <https://ml.comexp.net/metro_prototype>

- реальная запись в тоннеле: рабочий на пути, обнаружение и расстояние до него;

## Активация и лицензирование

Движок обнаружения входит в репозиторий в зашифрованном виде. Во время развертки Docker он привязывается
к конкретной машине на этапе `docker build` (когда есть интернет), а при запуске
расшифровывается только в оперативную память. На другой машине образ не запустится и выдаст
понятное сообщение: система является средством безопасности.
